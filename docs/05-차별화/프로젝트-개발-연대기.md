# 프로젝트 개발 연대기

정확한 커밋 목록은 Git log와 [전체 개편 상세 기록](../architecture/rework-history-2026-08-14.md)을 기준으로 하며, 아래는 면접에서 설명하기 위한 문제 해결 순서입니다.

## 1단계. 기본 업무와 역할 모델

원장·교사·학부모와 유치원·반·원생 관계를 정의하고 로그인·유치원·반·원생·출결·알림장·공지·캘린더 기본 흐름을 만들었습니다.

## 2단계. 보안 경계 강화

JWT cookie와 Redis refresh/session을 보강하고, URL 권한만으로 부족한 tenant·원생·반 관계 검증을 `AccessPolicyService`로 정리했습니다. rate limit, CSP, CSRF, CORS, prod startup safety도 추가했습니다.

## 3단계. 업무 상태 모델링

입학 신청을 pending/waitlist/offer/approved 등 상태로 분리하고, 출결 변경 요청을 원래 출결과 별도 workflow로 분리했습니다. 상태 전이·중복·권한 실패를 단위/통합 테스트로 고정했습니다.

## 4단계. 운영 실패를 제품 기능으로 승격

알림을 Outbox와 channel adapter로 분리하고 retry/backoff/dead-letter와 원장 운영 화면을 추가했습니다. 인증 감사와 업무 감사를 분리해 조사 가능성을 만들었습니다.

## 5단계. 성능·frontend·운영 품질

Notepad·Dashboard·Outbox query budget을 측정하고 개선했습니다. 페이지 JS 모듈화, inline handler 제거, local asset build, 접근성·reduced motion 검사, backup/restore·deploy SHA·readiness 자산을 정리했습니다.

## 6단계. 현재 판단

대표 기능·보안·성능·운영 전환 자산은 설명 가능한 상태지만 실제 HTTPS·운영 DB/Redis·provider sandbox가 연결되지 않았으므로 외부 운영 증거는 미완료입니다.
