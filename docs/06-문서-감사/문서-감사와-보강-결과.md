# 포트폴리오 문서 감사와 보강 결과

기준일: 2026-08-14

이 문서는 취업 포트폴리오로 읽힐 때 어디가 약했는지와 무엇을 보강했는지를 남기는 품질 감사 기록입니다.

## 1. 감사 결론

| 영역 | 감사 전 문제 | 보강 방향 |
| --- | --- | --- |
| 면접 기본기 | 프로젝트 질문 중심이라 Java·Spring·JPA·SQL 꼬리질문 대응이 약함 | 기술 질문 심화 은행 추가 |
| 구현 추적성 | 기능과 endpoint·service·test 연결이 흩어짐 | 요구사항 추적표 추가 |
| 설계 판단 | 선택한 결과는 있으나 버린 대안과 전환 조건이 부족함 | 의사결정 기록 추가 |
| 시간 흐름 | 6시간 개편 기록은 있으나 문제 발견→수정→검증 서사가 약함 | 개발 연대기 추가 |
| 수치 근거 | 개선 수치만 요약되고 재현 조건이 분산됨 | 성능 재현 절차 추가 |
| 사실 정확성 | Outbox에 실제 enum에 없는 `FAILED` 상태가 표기됨 | 코드 enum 기준으로 수정 |
| 차별성 | TownPet과 다르다는 표는 있으나 사례 연결이 약함 | 동일 역량의 다른 문제 비교 강화 |

## 2. 고친 사실 오류

실제 `NotificationDeliveryStatus` enum은 다음 네 상태만 갖습니다.

```java
PENDING, PROCESSING, DELIVERED, DEAD_LETTER
```

재시도 가능한 실패는 `scheduleRetry()`가 다음 실행 시각을 기록하고 `PENDING`으로 복귀시키며, 최대 시도 횟수를 넘은 실패만 `DEAD_LETTER`로 보냅니다. 문서의 상태 흐름을 이 구현에 맞췄습니다.

## 3. 문서 설명 품질 평가

| 항목 | 보강 전 | 목표 |
| --- | ---: | ---: |
| 문제 정의 | 3/4 | 4/4 |
| 기능·코드·테스트 추적성 | 2/4 | 4/4 |
| 설계 대안·trade-off | 2/4 | 4/4 |
| 성능·보안·운영 증거 | 3/4 | 4/4 |
| 면접 기본기·꼬리질문 | 1/4 | 4/4 |
| 합계 | 11/20 | 20/20 문서 목표 |

이 점수는 프로젝트 자체가 아니라 문서 설명 품질의 평가입니다. 실제 클라우드 운영 증거가 없는 한 프로젝트를 20/20으로 표현하지 않습니다.

## 4. 남은 한계

- 실제 운영 트래픽의 MySQL 실행계획과 p95는 아직 없습니다.
- 외부 email·push·incident provider sandbox 수신은 아직 없습니다.
- 실제 HTTPS 배포·rollback·운영 backup/restore는 외부 자격증명에 의존합니다.
- 성능 수치는 local Docker fixture와 제한된 k6 조건입니다.

이 한계는 숨길 항목이 아니라 “현재 증거”와 “다음 검증”을 분리해 답변하는 재료입니다.
