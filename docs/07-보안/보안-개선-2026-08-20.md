# DB 최소 권한 개선 완료

기준일: 2026-08-20

앱 DB 계정과 Flyway migration 계정을 분리했다.

- 앱 계정: `SELECT`, `INSERT`, `UPDATE`, `DELETE`만 허용
- Flyway 계정: 위 DML과 `CREATE`, `ALTER`, `DROP`, `INDEX`, `REFERENCES` 허용
- 두 계정 모두 `GRANT OPTION`과 root 사용을 금지
- `scripts/provision-mysql-privileges.sh`는 반복 실행 가능한 권한 reconciliation 스크립트다.
- netcup 배포는 MySQL health 확인 후 권한 적용을 완료해야 앱을 시작한다.
- 로컬 신규 MySQL volume은 `docker/init/01-apply-mysql-privileges.sh`로 동일 정책을 적용한다.
- 외부 RDS는 DB 접근이 가능한 운영 호스트에서 아래처럼 실행한다.

```bash
MYSQL_HOST=<rds-host> MYSQL_DATABASE=erp_db \
MYSQL_USER=erpadmin MYSQL_PASSWORD='<app-password>' \
FLYWAY_DB_USERNAME=erp_migrator FLYWAY_DB_PASSWORD='<migration-password>' \
MYSQL_ROOT_PASSWORD='<admin-password>' \
./scripts/provision-mysql-privileges.sh
```

검증 시 `SHOW GRANTS FOR 'erpadmin'@'%';`와 `SHOW GRANTS FOR 'erp_migrator'@'%';`를 실행해 앱 계정에 DDL/권한 위임이 없는지 확인한다. 실제 RDS 권한 증적은 운영 환경에서 별도로 보관해야 한다.
