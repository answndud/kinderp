## 3. 문서 작성 원칙

- 실제 구현된 기능과 테스트로 확인된 내용만 성과로 표현합니다.
- 실제 클라우드 배포나 외부 알림 provider 운영 연동은 완료했다고 표현하지 않습니다.
- 성능은 개선 전후 수치와 측정 조건을 함께 적습니다.
- AI 활용은 구현 대행이 아니라 문제 분해·누락 점검·검증 보조로 설명합니다.
- 기능 나열보다 `문제 → 설계 선택 → 구현 → 검증 → trade-off` 순서로 설명합니다.

## 4. 현재 상태의 정직한 표현

- Java 21, Spring Boot 3.5.14 기반의 MySQL·Redis 모놀리식 ERP입니다.
- 로컬/demo 프로파일과 Docker 실행 자산은 준비되어 있습니다.
- Testcontainers 통합 테스트, 성능 smoke, 보안·접근성·문서 링크 검사와 CI workflow가 있습니다.
- 실제 외부 HTTPS 배포, 운영 DB/Redis, OAuth redirect, 알림 provider sandbox 수신은 아직 외부 자격증명이 필요한 잔여 범위입니다.
